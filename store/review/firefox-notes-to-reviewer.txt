No user name or password: Nodkey has no account. The extension needs an iPhone with the free Nodkey app from the App Store (version 1.4 or later).

1. Click the Nodkey icon in the toolbar, then "Get a code".
2. On the iPhone, open Nodkey, then Agents > Add agent, and type the code.
3. The browser and the iPhone show the same check number. Click "Same number" in the browser and confirm it on the iPhone.
4. Open a sign-in page of a site that is saved in Nodkey and click the Nodkey button in the password field. Approve on the iPhone. The extension fills in the user name and the password.

New in {version}: Make a strong password.
- On a sign-up or password change page, click in the new password field, click the Nodkey button, then "Make a strong password". The iPhone asks with Face ID, makes a password that fits the field's rules, saves it in Nodkey and answers. The extension fills it into the new password field and the field that repeats it, and does not offer to save it again.
- The request holds the host and the page address (no query, no fragment), the page title, the user name of the form or of an earlier step of the same sign-up, whether it is a change, and the field's rules (passwordrules, minlength, maxlength, pattern). The earlier user name is kept in session storage for 5 minutes; it is not a secret. The password comes back end-to-end encrypted and is never stored.
- Rules that no password can meet are refused in the browser at once; nothing goes to the iPhone.
- A step that only chooses a new user name shows no Nodkey button. A suggested address that the person picks there goes on as the user name.
- The version number now follows the iPhone app: 1.4 of the extension goes with Nodkey 1.4. An older app answers "unsupported_kind", and the extension asks the person to update Nodkey.

Permissions: no change. Data collection: no change (the new request is authentication information, website activity and website content, which are declared already).

Source: https://github.com/peters/nodkey-browser (commit {commit}). The source package is attached.
Build: Node 24.21 (.nvmrc), Rust with wasm32-unknown-unknown and wasm-bindgen-cli (version in Cargo.lock). npm ci && npm run build. The package is dist/nodkey-firefox-{version}.zip.
The protocol code (WebAssembly) comes from https://github.com/peters/nodkey-cli at the revision in Cargo.toml ({proto}).

The innerHTML warnings: content.js sets a constant SVG icon string that is built into the package; the other uses are in the Vue runtime. No page or remote content goes into innerHTML.
