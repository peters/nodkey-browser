Nodkey needs an iPhone with the free Nodkey app from the App Store (version 1.3 or later). There is no account and no login.

To test:
1. Click the toolbar icon, then "Get a code".
2. In Nodkey on the iPhone: Agents > Add agent, type the code. The browser and the iPhone show the same check number: click "Same number" in the browser and confirm it on the iPhone.
3. Open a sign-in page of a site that is saved in Nodkey and click the Nodkey button in the field. Approve on the iPhone.

Passkey sign-in with Nodkey 1.3.0 on the iPhone: approve it from the Nodkey notification (keep Nodkey in the background, touch and hold the notification, then "Approve once" and Face ID). In 1.3.0 the approval screen inside the open app shows only Deny for a passkey sign-in; Nodkey 1.3.1 adds Approve there. Creating a passkey and unlocking a key with a passkey (PRF) are approved in the app as usual.

Cards: add a test card in Nodkey, then open Agents, this browser, turn on "May use cards" and pick the card. For a billing page with no total, also turn on "Add cards for later payments".

New in {version}:
- Pairing shows a check number on both screens, and every request and answer is signed (Ed25519; the browser's key is a non-extractable WebCrypto key).
- Sign-in methods: when the iPhone says that a site uses "Sign in with Google" (or Apple, GitHub, Microsoft, Facebook), the extension shows it and fills the provider login only on the provider's own sign-in hosts. It keeps that login in memory for 3 minutes for one tab, never in storage. At Google's "Check your phone", the Nodkey button can choose a passkey or a code from Nodkey. After a sign-in with a provider, the page can ask "Remember that <site> uses <provider> sign-in?"; "Remember" sends only the site and the provider's name.
- SMS codes: on a page that says that the code came by SMS, the Nodkey button asks the iPhone, which gets the code from the user's Shortcuts automation (it waits up to 2 minutes).
- The agent limit: the iPhone can ask with a notice, or pause the browser, after many new logins and codes in 24 hours. The extension shows a short, calm note and says where to resume.
- Passkeys with the PRF extension: the iPhone gives the PRF output for a passkey that it keeps.
- Cards for later payments on a billing page with no total (no amount), and card fields in a payment provider's frame (shown as "via <host>"). The shop is always the top-level page.
- An iPhone without a passcode gives no cards, and no passkey sign-in that needs user verification or PRF (refusal "no_passcode"). The extension says where to set a passcode.
- Security: a login or a code is filled only on the website of the account that the iPhone answered with; the in-page button acts only when it is visible and not covered; a passkey create or get needs a user click; the relay address must use https (http only for localhost), and relay redirects are refused.

Permissions: no change. Data collection: locationInfo is new. The relay keeps the IP address that the browser connects from and its country with each request (2 minutes, up to 6 for an SMS code), so the iPhone can show where the request came from. The privacy policy says so.

Source: https://github.com/peters/nodkey-browser (commit {commit}). The source package is attached.
Build: Node 24.21 (.nvmrc), Rust with wasm32-unknown-unknown and wasm-bindgen-cli (version in Cargo.lock). npm ci && npm run build. The package is dist/nodkey-firefox-{version}.zip.
The protocol code (WebAssembly) comes from https://github.com/peters/nodkey-cli at the revision in Cargo.toml ({proto}).

The innerHTML warnings: content.js sets a constant SVG icon string that is built into the package; the other uses are in the Vue runtime. No page or remote content goes into innerHTML.
